# Plan — PG-15: the menu stays open after a change in a meeting's row

Backlog: PG-15 (refines R-6, the menu of today's meetings, and R-14, the owner's overrides). PRD `docs/prd/meeting-guardian.md` §5, new bullet: a change made in a meeting's row never closes the menu; the same meeting stays expanded and shows the new state at once.
Architecture read: `interfaces.md` §3 (Controller ↔ UI: `render` is idempotent, the UI only draws and reports through `dispatch`), `overview.md` "UI layer" (ADR-0004), `boundaries.md` (`ui/` decides nothing; "how each directory is organised inside is the senior engineer's call"), `constraints.md` (per-tick work under 1 ms).

**Size: M.** One owner-visible behaviour, all inside `ui/` plus a one-line widening of `app/view.js`'s menu signature. No contract changes (the View shape, the actions and `dispatch` are unchanged), no new dependency, no stored data. It is not S: a new file in `ui/`, two GNOME item subclasses, an in-place redraw that replaces a rebuild, a fix in `app/view.js`, and three smoke checks (two rewritten, one new).

## What changes, and for whom

The calendar owner: clicking Must attend, Apply to whole series, Back to automatic, Switch to in person / online, or a travel time no longer closes the menu. The menu stays open, the same meeting stays expanded and shows its new state (after Switch to in person the travel choices are right there; after a pick the mark moves; after Switch to online they are gone). Other meetings stay collapsed. When the calendar refreshes while the menu is open, the expanded meeting stays expanded if it is still listed.

## Why it closes today (confirmed in GNOME Shell 50.5 `ui/popupMenu.js`)

1. **Close on activate.** `PopupMenuBase._connectItemSignals` connects every item's `activate` signal (with `ConnectFlags.AFTER`) to `itemActivated()`, which closes the top menu. `addAction` items emit `activate` on click, Enter and space. `PopupSwitchMenuItem.activate` toggles, then calls `super.activate()` (emits `activate`) for anything except the space key. `PopupSubMenuMenuItem.activate` is the one stock item that does **not** emit, which is why expanding a row keeps the menu open.
2. **Rebuild collapses.** Any change to `view.menu.signature` makes `Indicator._rebuildRows()` call `this._meetings.removeAll()` and build fresh rows, so even a menu that stayed open would lose its expanded row.
3. **A third trap the fix would walk into.** `PopupSwitchMenuItem.setToggleState()` emits `toggled`, the same signal a user's click emits. Today rows are rebuilt, so the switch is never set from code. Once rows are redrawn in place, setting the switch from the View would dispatch a `setVerdict` the owner never made. The design below makes that impossible.
4. **A stale header today.** `app/view.js` `signatureOf` leaves out `travel.header`, `isMust`, `travel.choices` and `modeSwitchLabel`. Most are implied by other fields, but `header` is not: picking a travel time equal to the default changes "Travel time: 30 min (default)" to "Travel time: 30 min" with the same minutes and target, so the signature does not change and the row keeps "(default)". With in-place redraw the signature is the only gate, so it must cover every drawn field.

### `ui/meetingRow.js` (new file, header comment: "One meeting's row in the top-bar menu (PRD §5). Its changes never close the menu (PG-15).")

Imports: `gi://Clutter`, `gi://GObject`, `gi://St`, `resource:///org/gnome/shell/ui/boxpointer.js`, `resource:///org/gnome/shell/ui/popupMenu.js`. Nothing else (all already allowed for `ui/` by the lint rules).

```js
/** A line in a meeting's row that does its action and leaves the menu open (PG-15). */
const RowAction = GObject.registerClass({ GTypeName: 'PayAttentionRowAction' },
class RowAction extends PopupMenu.PopupMenuItem {
    /**
     * @param {string} text
     * @param {() => void} onActivate
     */
    _init(text, onActivate) {
        super._init(text);
        this._onActivate = onActivate;
    }

    // Never emits 'activate': the menu closes on that signal (popupMenu.js itemActivated).
    activate(_event) {
        this._onActivate();
    }
});

/** The Must attend switch: reports only the owner's own changes, and leaves the menu open. */
const MustAttendSwitch = GObject.registerClass({ GTypeName: 'PayAttentionMustAttendSwitch' },
class MustAttendSwitch extends PopupMenu.PopupSwitchMenuItem {
    /**
     * @param {boolean} state
     * @param {(state: boolean) => void} onOwnerToggle called for a click, a key or a drag; never for showState()
     */
    _init(state, onOwnerToggle) {
        super._init('Must attend', state);
        this._drawing = false;
        this.connect('toggled', (_item, s) => {
            if (!this._drawing)
                onOwnerToggle(s);
        });
    }

    /** Draws the View's state. setToggleState emits 'toggled', so this is never reported as the owner's. */
    showState(state) {
        this._drawing = true;
        try {
            this.setToggleState(state);
        } finally {
            this._drawing = false;
        }
    }

    // Toggles without emitting 'activate' (Step 4).
    activate(_event) {
        this.toggle();
    }
});

export class MeetingRow {
    /**
     * @param {import('../app/view.js').MeetingRow} row
     * @param {(action: object) => void} dispatch
     */
    constructor(row, dispatch)

    /** @returns {PopupMenu.PopupSubMenuMenuItem} the item to add to the menu section */
    get item()

    /** @returns {string} the occurrence key this row draws */
    get key()

    /** @returns {boolean} whether the owner has this row open */
    get expanded()          // this._item.menu.isOpen

    /** Opens this row without animation (to carry an open row across a rebuild). */
    expand()                // this._item.menu.open(BoxPointer.PopupAnimation.NONE)

    /**
     * Redraws this meeting in place: same widgets, so an open row stays open.
     *
     * @param {import('../app/view.js').MeetingRow} row the same meeting
     * @throws {Error} when row.key is not this row's key
     */
    update(row)
}
```
- `RowAction` and `MustAttendSwitch` are **module-private**. Every line with an action in a row is one of them, built in one place, so no row line can close the menu.
- **Every click handler reads `this._row` at click time**, never a captured `row`. `this._row` and the widgets are replaced together inside `_draw`. This removes the reason the old signature had to include the travel target (a handler holding a stale target).
- **`update` throws** `new Error(\`MeetingRow: update for ${row.key} on the row of ${this._row.key}\`)` on a key mismatch: a row cannot be turned into another meeting; replacing a meeting is the indicator's rebuild.
- **`showState` is the only way the row sets the switch.** The owner's toggle and a drawn state cannot be confused.

**Inside `MeetingRow`** (private, decided here so nothing is left open):
- The constructor builds, in this order, the widgets of today's `_rowItem` and keeps them in fields: `_item` (`PopupSubMenuMenuItem(row.label)`), `_detail` (the `St.Label` with `payattention-row-detail`, inserted above `_item.label` as today), `_reason` (`PopupMenuItem`, `setSensitive(false)`), `_must` (`MustAttendSwitch`), `_series` (`RowAction('Apply to whole series', …)`), `_back` (`RowAction('Back to automatic', …)`), `_mode` (`RowAction(row.modeSwitchLabel, …)`), `_travel` (a `PopupMenu.PopupMenuSection`, added last). Then it sets `this._row = row` and calls `this._draw(row)`. One draw path for construction and update.
- Actions, each reading `this._row` (call it `r`):
  - `_must` → `dispatch({type: 'setVerdict', key: r.key, verdict: state ? 'must' : 'ignore', scope: 'occ'})`
  - `_series` → `dispatch({type: 'setVerdict', key: r.key, verdict: r.isMust ? 'must' : 'ignore', scope: 'series'})`
  - `_back` → `setVerdict … verdict: null, scope: 'occ'`, then, if `r.recurring`, the same with `scope: 'series'` (today's order)
  - `_mode` → `dispatch({type: 'setMode', key: r.key, mode: r.otherMode})`
  - a travel choice of `minutes` → `dispatch({type: 'setTravel', target: r.travel.target, minutes})`
- `_draw(row)`:
  1. `const hadFocus = this._focusInRow();` where `_focusInRow()` is `const f = global.stage.get_key_focus(); return f !== null && f.mapped && this._item.menu.actor.contains(f);` (`mapped` matters: a hidden line can keep key focus while no longer shown).
  2. `this._row = row`; `_item.label.text = row.label`; `_detail.text = row.detail`; `_reason.label.text = row.reason`; `_must.showState(row.isMust)`; `_series.visible = row.recurring`; `_back.visible = row.overridden`; `_mode.label.text = row.modeSwitchLabel`; `this._drawTravel(row.travel)`.
  3. `if (hadFocus && !this._focusInRow()) this._must.grab_key_focus();` A keyboard owner whose line was just hidden or rebuilt lands on the always-present switch instead of nowhere.
- `_drawTravel(travel)`: the section holds the header and the choice lines. `this._travelShape` (initially `undefined`) is `travel === null ? null : travel.choices.join(',')`. When the new shape differs from the old: `this._travel.removeAll()`, `this._choices = []`, and if `travel !== null` add the header (`PopupMenuItem`, `setSensitive(false)`, kept as `this._header`) then one `RowAction(\`${minutes} min\`, …)` per choice, pushed to `this._choices` as `{minutes, item}`. Then, when `travel !== null`: `this._header.label.text = travel.header` and each choice `item.setOrnament(minutes === travel.minutes ? PopupMenu.Ornament.DOT : PopupMenu.Ornament.NO_DOT)`. The choice list is `TRAVEL_CHOICES_MIN` or `[]` today, so in practice the section is rebuilt only when the meeting switches mode; a pick only moves the dot.

### `ui/indicator.js`
```js
// fields: this._rows = [] (MeetingRow[], in the section's order); _signature, _pendingRows, _rebuildId as today

/** True when both lists hold the same keys in the same order. */
function sameKeys(rowsDrawn, rows)    // module-private: lengths equal and every rowsDrawn[i].key === rows[i].key

_drawRows()                            // replaces _rebuildRows()
```
`_drawRows()`:
```js
const rows = this._pendingRows;
this._pendingRows = null;
if (sameKeys(this._rows, rows)) {
    rows.forEach((row, i) => this._rows[i].update(row));
    return;
}
// A meeting came, went or moved: rebuild, and keep the open row open if it is still listed.
const openKey = this.menu.isOpen ? (this._rows.find(r => r.expanded)?.key ?? null) : null;
this._meetings.removeAll();
this._rows = rows.map(row => new MeetingRow(row, this._dispatch));
for (const r of this._rows)
    this._meetings.addMenuItem(r.item);
this._rows.find(r => r.key === openKey)?.expand();
```
- The idle deferral in `update()` stays, with its comment reworded: "Deferred: this may run inside a menu item's own handler, and a redraw can destroy that item (a rebuild, or the travel lines of a mode switch)."
- Why two paths and not one keyed reconcile: `PopupMenuBase.moveMenuItem` moves a `PopupSubMenuMenuItem` without its submenu actor, so reordering in place would need GNOME internals. Owner actions never change the key list (rows are filtered by time only), so they always take the in-place path; only a calendar change or the passing of time takes the rebuild path, and it re-expands by key.
- **Misuse made impossible:** `this._rows` and the section's children change only together, in `_drawRows`.

- A click on a `RowAction` or the switch still closes the menu: something other than the `activate` signal closes it, and the design is wrong.
- Clicking or dragging the switch's handle reports two toggles (both `toggled` from the handle and an `activate` from the item), or none.
- Making a check pass needs a GNOME private field (`_switch`, `_ornament`, `_getMenuItems`, `_openedSubMenu`…) in `extension/`. Production code uses only the public API named here.
- `addToStatusArea('payattention-smoke-rows', …)` or importing the installed `indicator.js` from the smoke registers a second GType or otherwise fails (the `GTypeName`s must be registered once per shell, as `card.js` is in `6b`).
- The per-tick timing test fails after Step 1.
- Two rows in one View share a key.
