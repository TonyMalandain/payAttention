# Plan — PG-1a: the judgment and timing rules (core logic and project dev tooling)

**Sensitive:** personal data. Calendar titles, attendee addresses, places and links are other people's data.
- Core never logs anything; it has no logger at all.
- The protocol validator reports field *paths* only, never values.
- "Join" links are restricted to `https:` URLs on the conferencing allowlist, with no user-info part.
- Tests use synthetic data only (`*.test` domains). No real calendar data goes into the repo.

## What changes, and for whom

Nothing is visible to the calendar owner yet. This ticket delivers `extension/core/`, the pure functions that PG-1b (helper) and PG-1c (shell/UI) call:
- the verdict with its reason (PRD §1)
- online or in person (§2)
- deadline, current step, visibility, snooze, overlap, cutoff and "return after away" (§3, §4)

- the helper protocol validator
- the stored key formats and the alert-state reducer

It also delivers the dev tooling: `package.json`, `eslint.config.js` with the per-directory import rules, the `node --test` setup, and `.gitignore`.

## Seams (exact signatures)

### `protocol.js`: imports nothing, so the helper can import it alone

```js
export const PROTOCOL_VERSION = 1;
export const MAX_LINE_LENGTH = 4 * 1024 * 1024;          // characters
export const MAX_DESCRIPTION_LENGTH = 32768;
export const PARTSTATS, CUTYPES, ROLES, STATUSES, TRANSPARENCIES, REFRESH_REASONS  // frozen string arrays (values as in the typedefs; REFRESH_REASONS = ['resume','manual'])
export function validateHelperMessage(obj) -> {ok:true, message:object} | {ok:false, code:string, field?:string}
export function parseHelperLine(line: string) -> same result type
export function formatHelperMessage(message: object) -> string      // JSON + '\n'; throws TypeError(`invalid helper message: ${code}${field ? ' at ' + field : ''}`)
export function parseShellLine(line: string) -> {ok:true, message:{type:'refresh',reason:'resume'|'manual'}} | {ok:false, code:string, field?:string}
export function formatShellMessage(message: object) -> string       // JSON + '\n'; throws TypeError the same way
```

**Failure codes:**
- `'too-large'`
- `'bad-json'`
- `'bad-message'` (the value is not a plain object)
- `'unknown-type'`
- `'protocol-mismatch'`
- `'invalid-hello'`, `'invalid-snapshot'`, `'invalid-status'`, `'invalid-refresh'`

**`field`** is a path such as `events[3].attendees[0].partstat`, and never contains a value.

**Parsing rules:**
- The parsers strip one trailing `\n` or `\r\n`.
- The length check applies to the raw line, before `JSON.parse`.
- Unknown extra properties are accepted and left as they are, for forward compatibility.

**What the validator checks:**

- **hello:** `protocol === 1`, otherwise `protocol-mismatch`.
- **snapshot:**
  - `protocol === 1`, otherwise `protocol-mismatch`.
  - `generatedAt`, `rangeStart` and `rangeEnd` are finite numbers.
  - `sources[]` entries: `uid`, `name` and `backend` are strings; `ownerEmail` is a string or null; `ok` is a boolean; `error` is a string or null.
  - `events[]`: every DTO field has the type in `OccurrenceDTO`.
    - `uid` is a non-empty string.
    - `start` and `end` are finite numbers.
    - `recurrenceId` is a finite number or null.
    - The enums hold the listed values.
    - `description.length <= 32768`.
    - `conferenceUris` is an array of strings.
    - `organizer` is null or an object with string `email` and `name`.
    - `attendees` is an array of fully typed `Attendee` objects.
  - The **first** failing field is reported, walking the fields in DTO order.
- **status:** `level` is `'warn'` or `'error'`, and `code` is a string of 1 to 64 characters matching `/^[a-z0-9][a-z0-9._-]*$/`.

Each misuse this seam rules out:
- Neither side can write a non-protocol line through `format*` (it throws).
- A validation result can never leak event content into a log (it carries paths only).
- The helper cannot pull in the rest of core by importing this module.

### `words.js`

```js
export const BUILTIN_IGNORE_WORDS = ['hold','placeholder','block','blocked','focus','focus time','deep work','lunch','break',
  'commute','travel','ooo','out of office','busy','tentative hold','do not book','dnb','reminder','gym'];      // frozen, PRD order
export const BUILTIN_IMPORTANT_WORDS = ['interview','client','customer','board','investor','candidate','exec','review with',
  'demo','pitch','contract','legal','offsite','1:1','1-1','one on one'];                                     // frozen, PRD order
export const NOT_A_PLACE_WORDS = ['online','virtual','remote','tbd','tba','n/a','none','zoom','google meet','microsoft teams',
  'microsoft teams meeting','teams','teams meeting','webex','whereby','jitsi','goto meeting','gotomeeting','slack huddle',
  'huddle','video call','phone','phone call'];                                                               // frozen
export function compileWords(builtin: string[], extra: string[]) -> WordMatcher   // opaque frozen object; compile once per judge() call
export function findWord(matcher: WordMatcher, text: string) -> string|null       // the list word that matched, normalised
```

**`compileWords`:**
1. Normalise every word: trim, collapse whitespace to one space, lowercase. Drop empty words and duplicates.
2. Order the list by length, descending, so the most specific phrase wins ("focus time" before "focus"). Ties keep list order, builtins first.
3. Per word, build the regex `(?<![\p{L}\p{N}])` + escaped word, with each space replaced by `\s+`, + `(?![\p{L}\p{N}])`, flags `iu`. Escape every regex special character.

**`findWord`** returns the first word in that order whose regex matches `text`.

Only a `WordMatcher` from `compileWords` is accepted, so regex compilation cannot drift into a per-occurrence loop. `findWord` throws `TypeError` if it is given anything else; check a private symbol property.

### `links.js`

```js
export const CONFERENCING_HOSTS = [ {host:'meet.google.com'}, {host:'zoom.us'}, {host:'zoomgov.com'},
  {host:'teams.microsoft.com'}, {host:'teams.live.com'}, {host:'webex.com'}, {host:'whereby.com'},
  {host:'meet.jit.si'}, {host:'8x8.vc'}, {host:'meet.goto.com'}, {host:'gotomeeting.com'}, {host:'gotomeet.me'},
  {host:'app.slack.com', pathPrefix:'/huddle/'} ];                                      // frozen
export function extractUrls(text: string) -> string[]
export function parseHttpsUrl(url: string) -> {host:string, path:string}|null
export function isConferenceUrl(url: string) -> boolean
```

**`extractUrls`:**
- Uses the regex `/https?:\/\/[^\s<>"'`()\[\]{}]+/gi`.
- For each match, strips trailing characters matching `/[.,;:!?]+$/` and replaces every `&amp;` with `&`.
- Returns the URLs in text order.

**`parseHttpsUrl`** is a hand parser, because gjs has no `URL`:
1. Match `/^https:\/\/([^\/?#]*)(.*)$/i`, else return null.
2. If the authority contains `@`, return null.
3. Host = authority without a trailing `:<digits>`, lowercased, without one trailing `.`. It must be non-empty and match `/^[a-z0-9.-]+$/`, else return null.
4. Path = the rest up to the first `?` or `#`; `'/'` if the rest is empty or does not start with `/`.

**`isConferenceUrl`** is true when:
- `parseHttpsUrl` succeeds,
- some entry has `host === e.host || host.endsWith('.' + e.host)`,
- and, where the entry has a `pathPrefix`, the path starts with it.

### `owner.js` (internal)

```js
export function ownerIdentity(snapshot: Snapshot, config: JudgeConfig) -> {addresses:Set<string>, domains:Set<string>}
export function ownerFacts(event: OccurrenceDTO, identity) -> {role:'organizer'|'attendee'|'not-listed'|'unknown',
                                                               partstat:'accepted'|'declined'|'tentative'|'unanswered'|null,
                                                               guests:string[]}
```

**Normalising an address:** trim, lowercase, strip a leading `mailto:`.

**`ownerIdentity`:**
- **Addresses** = every non-null `sources[].ownerEmail` (from **all** sources) ∪ `config.extraOwnerAddresses`, normalised, empty ones dropped.
- **Domains:**
  - If `config.ownerDomains` has entries, use them: trimmed, lowercased, one leading `@` stripped, empty ones dropped.
  - Otherwise use the part after the last `@` of every owner address.

**`ownerFacts`:**
- **Guests:** the people are attendees with `cutype` in {individual, unknown, group}, plus the organiser if one is present. Collect their normalised emails and de-duplicate the non-empty ones; entries with an empty email each count once. `guests` = those whose email is not an owner address.
- **Role:**
  - `'unknown'` if `addresses.size === 0`;
  - otherwise `'organizer'` if the organiser's email is an owner address;
  - otherwise `'attendee'` if some attendee's email is an owner address;
  - otherwise `'not-listed'`.
- **Partstat:**
  1. If attendees match owner addresses, take the best of their partstats in the precedence accepted > tentative > needs-action > delegated > other > declined. Map it: accepted → `'accepted'`, tentative → `'tentative'`, declined → `'declined'`, anything else → `'unanswered'`.
  2. Else, if the role is `'organizer'`, `'accepted'`.
  3. Else null.

### `verdict.js` (internal)

```js
export const REASON_CODES = [...all ReasonCode values...];   // frozen
export function ruleVerdict(event: OccurrenceDTO, facts, ctx: {ignore:WordMatcher, important:WordMatcher,
                            ownerDomains:Set<string>, largeMeetingSize:number}) -> {verdict, reasonCode, reason}
export function overrideVerdict(value: 'must'|'ignore') -> {verdict, reasonCode, reason}
```

`ruleVerdict` implements PRD §1 steps 2 to 5. **The first matching rule wins**, in exactly this order. `n` = `facts.guests.length`, and `plural(n)` = `n === 1 ? '1 guest' : `${n} guests``.

| # | Condition | verdict | reasonCode | reason (exact text) |
|---|---|---|---|---|
| 2a | `event.status === 'cancelled'` | ignore | cancelled | `cancelled` |
| 2b | `facts.partstat === 'declined'` | ignore | declined | `you declined` |
| 2c | `facts.role === 'not-listed' && n >= 1` | ignore | not-invited | `not invited: someone else's meeting` |
| 2d | `event.allDay \|\| !Number.isFinite(event.start)` | ignore | all-day | `all-day event` |
| 2e | `event.transparency === 'transparent'` | ignore | free | `marked as free time` |
| 2f | `findWord(ignore, event.summary)` → w | ignore | ignore-word | `placeholder: '${w}'` |
| 3a | `findWord(important, event.summary)` → w | must | important-word | `important: '${w}'` |
| 3b | `facts.role === 'organizer' && n >= 1` | must | organizer | `you organised it, ${plural(n)}` |
| 3c | `ownerDomains.size > 0` && some guest email has a domain (after the last `@`, non-empty) not in `ownerDomains` && `partstat` ∈ {accepted, unanswered} | must | external | `external guests` |
| 4a | `n === 0` | ignore | no-guests | `no other guests: personal block` |
| 4b | `n > largeMeetingSize && facts.role === 'attendee'` | ignore | large | `large meeting (${n} guests): absence unlikely noticed` |
| 5a | `2 <= n <= largeMeetingSize` && partstat ∈ {accepted, unanswered} | must | small | `small meeting (${n} guests): absence noticed` |
| 5b | `2 <= n <= largeMeetingSize && partstat === 'tentative'` | ignore | maybe | `you answered maybe` |
| 6 | otherwise | must | insufficient-data | `not enough information: treated as must-attend` |

`overrideVerdict`:
- `'must'` gives `{must, 'override-must', 'you marked this must-attend'}`.
- `'ignore'` gives `{ignore, 'override-ignore', 'you marked this ignore'}`.

### `attendance.js` (internal)

```js
export function detectAttendance(event: OccurrenceDTO) -> {detected:'online'|'in-person'|'unknown', link:string|null, placeText:string}
```

- **link:** the first candidate for which `isConferenceUrl` is true, checking in this order:
  1. each `conferenceUris[i].trim()` (used whole, no extraction);
  2. `extractUrls(location)`;
  3. `extractUrls(description)`.
- **placeText:**
  1. Take `location` with every match of the `extractUrls` regex replaced by `' '`, collapse whitespace, and trim; call it `p`.
  2. Build the comparison form of `p`: lowercase it and strip leading and trailing characters matching `[\s.,;:!?()\[\]{}"'-]`.
  3. If the comparison form is empty or is in `NOT_A_PLACE_WORDS`, `placeText = ''`; else `placeText = p`.
- **detected:** `link ? 'online' : placeText ? 'in-person' : 'unknown'`.

### `judge.js`

```js
export function judge(snapshot: Snapshot, config: JudgeConfig, overrides: Overrides, travel: TravelTimes) -> JudgedOccurrence[]
```

**Input checks.** All four arguments are required. The checks, each failing with `TypeError('judge: <what> …')`:
- `snapshot.events` and `snapshot.sources` are arrays;
- each of the six `JudgeConfig` fields has its type (the string arrays hold only strings);
- `largeMeetingSize` is an integer >= 1 and `defaultTravelMinutes` is a finite number >= 0;
- `overrides.verdict` and `overrides.mode` are objects, and `travel` is an object.

Passing the whole `Settings` object as `config` is allowed and intended.

**Algorithm** (one pass, so the O(n) shape is part of the design):
1. `identity = ownerIdentity(snapshot, config)`. `ignore = compileWords(BUILTIN_IGNORE_WORDS, config.extraIgnoreWords)`, `important = compileWords(BUILTIN_IMPORTANT_WORDS, config.extraImportantWords)`. All compiled once.
2. For each event, in array order:
   - `key = occurrenceKey(event)` and `sKey = seriesKey(event)`.
   - **Verdict override:** `ov = own(overrides.verdict, key) ?? own(overrides.verdict, sKey)`. Only the values `'must'` or `'ignore'` count; anything else is treated as absent. Use `Object.hasOwn`.
   - `v = ov ? overrideVerdict(ov) : ruleVerdict(event, ownerFacts(event, identity), ctx)`.
   - **Mode:** `att = detectAttendance(event)`. `mo` = the mode override, looked up the same way, valid values `'online'` or `'in-person'`. `mode = mo ?? (att.detected === 'in-person' ? 'in-person' : 'online')`.
   - **Join link:** `joinUrl = mode === 'online' ? att.link : null`.
   - `pKey = placeKey(att.placeText)`.
   - **Travel:** if `mode === 'in-person'`, look up `t = own(travel, pKey)` (only when `pKey` is not null). A valid `t` is an integer from 1 to 1440; if valid, `travelMinutes = t` and `travelIsDefault = false`, else `config.defaultTravelMinutes` and `true`. If `mode === 'online'`, `travelMinutes = null` and `travelIsDefault = false`.
   - **Deadline:** null when `event.allDay` or `!Number.isFinite(event.start)`. Otherwise `mode === 'in-person' ? start - travelMinutes*60000 : start`.
   - Build the `JudgedOccurrence`, with `title = event.summary` and `start`/`end` from the event (null if not finite).
3. **Merge duplicates by `key`.** Keep one result per key:
   - the **first result whose verdict is `'must'`**, in event order;
   - if none of them is must, the first result.

   This errs toward warning.
4. Sort by `start` ascending (null last), then by `key`. Freeze and return.

### `alertState.js`

```js
export function emptyAlertState() -> AlertState                         // {v:1, items:{}} frozen
export function parseAlertState(text: string|null|undefined) -> AlertState
export function serializeAlertState(state: AlertState) -> string        // JSON.stringify
export function reduce(state: AlertState, action: AlertAction, now: number) -> AlertState
```

**`parseAlertState`:**
- Returns empty when the text is not a non-empty string, JSON parsing fails, the result is not a plain object, `v !== 1`, or `items` is not a plain object (arrays are rejected).
- Otherwise keeps each item that is valid:
  - `start` is finite;
  - `done` ∈ {null, 'ack', 'skip'};
  - `doneAt`, `snoozeUntil` and `headsUpShownAt` are each null or finite.
- Invalid items are dropped individually.
- Never throws.

**`reduce`** returns a new frozen state and never mutates its input. It throws `TypeError` on an unknown `type`, or if `key` is not a non-empty string or `start`/`until` is not finite (not applicable to `prune`).

**`prev`** means `items[key]` only if its `start === action.start`; an item with a different start is replaced as if it were absent. **`base`** means `prev ?? {start, done:null, doneAt:null, snoozeUntil:null, headsUpShownAt:null}`.

| Action | Effect |
|---|---|
| `ack` / `skip` | `items[key] = {...base, done: type, doneAt: now, snoozeUntil: null}` |
| `snooze` | Return the **same** `state` object when `until <= now` or `base.done !== null`. Otherwise `items[key] = {...base, snoozeUntil: until}`. |
| `headsUpShown` | Return the same `state` object when `base.headsUpShownAt !== null` or `base.done !== null`. Otherwise `items[key] = {...base, headsUpShownAt: now}`. |
| `prune` | Drop every item whose `occurrenceKeyTime(key)` is null, or where `isExpiredOccurrenceKey(key, now)` is true. |

### `plan.js`

```js
export function plan(now: number, judged: JudgedOccurrence[], alertState: AlertState, timing: Timing, env: PlanEnv) -> Plan
export function actionFor(card: Card, type: 'ack'|'skip'|'snooze'|'headsUpShown') -> AlertAction
```

**Input checks.** `plan` checks:
- `now` is finite;
- `judged` is an array;
- `alertState.items` is an object;
- all 12 `Timing` numbers are present and finite;
- `env.userActive` and `env.dataHealthy` are booleans.

Otherwise it throws `TypeError('plan: …')`.

**Clamping, per call.** For each mode's offsets:
- `o1 = max(0, headsUpMs)`
- `o2 = min(max(0, nudgeMs), o1)`
- `o3 = min(max(0, insistMs), o2)`
- `o4 = min(max(0, takeoverMs), o3)`

**The algorithm.** For each `j` in `judged` with `verdict === 'must'` and finite `deadline` and `start`:

- **Offsets and times:**
  - Use the online offsets when `j.mode === 'online'`, otherwise the in-person offsets.
  - Step times are `Ti = deadline - oi`.
  - The cutoff is `start + cutoffMs`.
- **Alert-state item:** `item = own(alertState.items, j.key)`. If `item.start !== j.start`, treat it as absent (the meeting moved).
- **Indicator candidate.** `j` is one when:
  - `item?.done !== 'skip'`, and `now < cutoff`, and `deadline - now <= 12 h`;
  - and either `item?.done !== 'ack'` or `now < deadline`.
- **Active.** `j` is active when `item?.done` is null or absent, `now < cutoff`, and `now >= T1`. Then `step` = the highest i with `Ti <= now`.
- **Visibility:**
  - `snoozed = item?.snoozeUntil != null && now < item.snoozeUntil`.
  - Step 1: `visible = !snoozed && (item?.headsUpShownAt == null || now < item.headsUpShownAt + headsUpDisplayMs)`.
  - Steps 2 to 4: `visible = !snoozed`.
- **Card values:**
  - `snoozeUntil = step < 4 ? min(now + snoozeMs, T(step+1)) : now + takeoverSnoozeMs`.
  - `recordHeadsUpShown = step === 1 && visible && item?.headsUpShownAt == null && env.userActive`.

After the loop:

- **Primary.** Sort active candidates by:
  1. `visible` first;
  2. then `step === 4 && visible` first (a takeover is never hidden behind a lower step);
  3. then `deadline` ascending;
  4. then `key`.

  Primary = the first (or null).
- **The rest:**
  - `also` = the remaining **visible** active candidates, sorted by deadline then key, as `{key, step}`.
  - `takeover = !!primary && primary.visible && primary.step === 4`.
  - `indicator` = the indicator candidate with the smallest deadline (then key), as `{key, deadline, msToDeadline: deadline - now}`, or null.
  - `dataHealthy = env.dataHealthy`.

**`actionFor`:**
- It is the only sanctioned way to build per-occurrence actions. The controller calls `reduce(state, actionFor(card, 'snooze'), now)`, and for Join it calls `actionFor(card, 'ack')` after opening `joinUrl`.
- It returns `{type, key: card.key, start: card.start}`, plus `until: card.snoozeUntil` for `'snooze'`.
- It throws `TypeError` for any other type.

The controller dispatches `actionFor(plan.primary, 'headsUpShown')` whenever `plan.primary?.recordHeadsUpShown` is true. That replaces a UI `headsUpShown(key, at)` callback, and PG-1c will do the wiring.

Misuse this rules out:
- A snooze cannot outlive its step, because its end comes from `plan`, not from the caller.
- A heads-up cannot be consumed while the owner is idle.
- Passed steps cannot be replayed.
- Out-of-order settings cannot hide a step or reorder them.

  - **A snoozed meeting gives way:** A at step 2 is snoozed, B is visible. Primary B, `also` = `[]`.
  - **Everything snoozed:** only A, snoozed. Primary A with `visible` false, and takeover false.
  - **`also` order:** three at step 2 or higher are sorted by deadline.

  **Indicator:**
  - A must-attend meeting with deadline `S+12*HOUR`, at `S`: indicator is that key with `msToDeadline` 12 h. At `S-1`: null (more than 12 h away).
  - A closer ignorable meeting is not chosen.
  - A deadline passed, not acknowledged, before the cutoff: the indicator is that meeting with a negative `msToDeadline`.
  - `dataHealthy` passes through: env `dataHealthy:false` gives `plan.dataHealthy === false`.

  **Purity and input checks:**
  - Deep-frozen inputs do not throw, and the returned plan is frozen.
  - `plan(S, [], E, TIMING, {userActive:true})` throws `TypeError /dataHealthy/`.
  - A timing without `cutoffMs` throws `/cutoffMs/`.
- **Then:** `plan.js`.
- **Why here:** ADR-0002, the time model in `overview.md`, PRD §3, D-008.
- **Behaviour change:** new.
