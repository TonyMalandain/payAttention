# Plan — PG-14: a place means in person; every in-person meeting can get a travel time

Backlog: PG-14 (refines R-10 "online or in person" and R-11 "in-person meetings count down to the leave-by time").
Product: D-038 (a place means in person, supersedes D-007), D-039 (travel time with or without a place), D-040 (Join on every meeting with a link; "Clear travel times" clears both), PRD `docs/prd/meeting-guardian.md` §2, §3 (Join), §4.
Architecture (decided): ADR-0014 (one travel target per meeting), `data.md` (`meeting-travel-times`, `a{si}`, keyed by `series:<uid>`), `interfaces.md` §2 (mode rule, place-text rule 2 and its vocabulary, `joinUrl` whatever the mode, `travelTarget`) and §3 (`readTravel` → `{byPlace, byMeeting}`, writer `setTravel(target, minutes)`, action `setTravel {target, minutes}`, View travel), `testing-and-build.md` (online/in-person and travel-target expectations).

**Size: L.** Three owner-visible behaviours (mode rule, place-text rule, travel for placeless meetings), one new stored key (one-way door, already decided), internal contract changes across `core/`, `app/`, `shell/` and `ui/`, a hand edit of the rules golden, and new checks in the store check, the smoke ladder, prefs, the uninstall check and the sample. Every step is shallow; there are many of them. The steps land as separate commits in the order below.

## What changes, and for whom

The calendar owner:
- A meeting whose location names a physical place is **in person**, even with a video link. Only a link, a location like "Zoom" or "Join Zoom Meeting", or no location at all, is **online**. The owner's switch still wins.
- Join stays on every meeting with a video link, in person too.
- **Every** in-person meeting has travel choices in its menu row and "Change time" on its heads-up and nudge card. With a place, a pick is remembered for the place (as today). With no place (an online meeting the owner switched to in person), it is remembered for the series, or for that one meeting when it does not repeat. The alert times move at once.
- "Clear travel times" in Settings clears both kinds. `--purge` erases both; a plain uninstall keeps both.

### `core/words.js`
```js
/** Words a location can be made of and still name no place (PRD §2, interfaces.md §2 rule 2). */
export const VIDEO_CALL_WORDS = Object.freeze(['zoom', 'microsoft teams', 'teams', 'google meet', 'meet', 'webex',
    'google hangouts', 'hangouts', 'hangout', 'whereby', 'jitsi', 'goto meeting', 'gotomeeting', 'slack huddle',
    'huddle', 'join', 'meeting', 'call', 'online', 'video', 'besprechung', 'beitreten']);

/**
 * Whether `text` is made only of list words: once every whole-word occurrence of
 * every list word (longest first) is taken out, no letter or digit is left.
 * Also true for text that has no letter or digit at all.
 *
 * @param {WordMatcher} matcher from compileWords()
 * @param {string} text
 * @returns {boolean}
 * @throws {TypeError} when `matcher` did not come from compileWords()
 */
export function isMadeOfWords(matcher, text)
```
- Deliberately **not** in the list: `microsoft`, `google`, `slack`, `goto` alone (company names; "Microsoft" must stay a place), and `remote`, `tbd`, `n/a`, `none`, `phone` (whole-location words; rule 1 only, `interfaces.md` §2).
- `compileWords` gains one more field on the (opaque, frozen) matcher: `anyWord`, a single `RegExp` with flags `'giu'`: `(?<![\p{L}\p{N}])(?:<w1>|<w2>|…)(?![\p{L}\p{N}])`, alternatives in the same longest-first order as `entries`, each built exactly like today's per-entry pattern. Extract today's inline pattern (`escapeRegex(word).replace(/ /g, '\\s+')`) into a private `wordPattern(word)` used by both. For an empty list, `anyWord` is `/(?!)/gu`. **Do not `Object.freeze` the RegExp** (`replace` with a global regex writes `lastIndex`; a frozen one throws). `isMadeOfWords` is `!/[\p{L}\p{N}]/u.test(text.replace(matcher.anyWord, ' '))`, after the same `COMPILED` check as `findWord`. Existing callers of `compileWords`/`findWord` see nothing: the matcher is opaque.
- **Misuse made impossible:** the only way to get a matcher is `compileWords`, so the vocabulary is compiled once and cannot be handed in raw; one regex per location keeps the `judge` budget.

### `core/judge.js`
```js
export function judge(snapshot, config, overrides, travel, aiVerdicts)   // travel: TravelTimes
```
- `checkInputs`: `travel` must be a plain object whose `byPlace` and `byMeeting` are plain objects, else `TypeError('judge: travel.byPlace and travel.byMeeting must be objects')`. An old flat map (`{hq: 45}`) is refused rather than silently read as "no travel times".

  ```js
  /** The one travel entry an in-person meeting reads and a pick writes (ADR-0014); null when online. */
  function travelTargetOf(mode, pKey, sKey)   // -> Readonly<TravelTarget>|null
  ```
  `null` when `mode !== 'in-person'`; else frozen `{kind: 'place', key: pKey}` when `pKey !== null`, else frozen `{kind: 'meeting', key: sKey}`. Travel minutes are read from **that entry only**: `own(target.kind === 'place' ? travel.byPlace : travel.byMeeting, target.key)`, invalid or missing → `config.defaultTravelMinutes` with `travelIsDefault: true`. No fallback between maps.
- **Misuse made impossible:** no layer outside core can build or choose a target; the value shown and the value a pick overwrites are the same entry by construction.
